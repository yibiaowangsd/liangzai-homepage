## 实现

- `0011_news_read_indexes.sql` 为北京时间日期、板块和时间排序增加局部复合索引；保留原索引、文章及投递记录。日期表达式与历史查询完全一致，支持 UTC 和带偏移的时间戳。
- 日期列表采用递归索引定位，每轮寻找上一有新闻的日期，并与日刊清单合并。完整保留历史日刊、空板块说明、日期跳转、一天一页及末页行为；无需维护另一套日期计数表。
- 搜索保留标题/摘要/正文/标签/来源、中文别名、技术名分隔符、单字符拼写容错、排序及准确总数。将逐文章的 `json_each` 循环改为绑定 JSON 的标量取值，减少读取；任意子串与短中文搜索仍需要扫描已发布文章，不声称已实现索引全文检索。
- 仅验证后的公开新闻 GET 使用 Workers Cache API。缓存键只包含有效参数和发布版本，忽略无关缓存破坏参数；全局时间桶保证旧快照最多保留 60 秒。发布后所有机房最迟 60 秒看到新数据。Cache API 按机房存储，没有声称发布请求可以立即清除所有机房缓存。
- 缓存命中不访问 D1。授权头、Cookie、管理操作、订阅令牌、POST、404 和错误响应均不缓存；跨域响应按本次请求重新生成。
- 缓存未命中限额：普通新闻每 IP 每分钟 120 次；搜索每 IP 每分钟 12 次；搜索另外共用每机房每分钟 30 次的未命中额度。使用 Cloudflare Rate Limiting binding，不通过 D1 写计数器。此限制是按机房尽力执行的保护，不是账号每日配额的严格全局预算。
- 被限流返回 429，D1 配额类故障返回 503，均提供 `Retry-After: 60`。不将读取失败伪装成空新闻或缓存错误结果。已有成功缓存可在其 60 秒有效期内继续返回。
- `news_read` 结构化日志记录路由类型、缓存状态、状态码、查询数、`rows_read`、SQL/请求耗时，不写入 IP、查询词、令牌或订阅信息。保留 30 分钟投递周期、审核、邮箱确认、幂等投递及八板块选择逻辑。

## 部署与复核

1. PR 检查执行类型、lint、构建、新闻单元及 workerd 集成测试、浏览器新闻/日历/订阅流程。部署前再运行不依赖第三方包的核心回归。
2. 现有 `Deploy news API Worker` 工作流先应用迁移，再部署绑定及 Worker；`keep_vars` 保留已有服务配置。未升级套餐、未新增付费数据库或外部缓存。
3. 部署成功触发 `Diagnose D1 news reads`，用既有凭据读取 SQL 计划、真实 `meta.rows_read`/耗时、日用量和请求来源，重复少量 URL 验证缓存。健康接口的 `news_release` 与部署 SHA 应相同。
4. 诊断只做公开接口读取、聚合统计及 EXPLAIN，不运行投递、补发或订阅写入。取不到的 API、数据集或权限写入报告 `unavailable`；接口状态和部署 SHA 不符会使部署后诊断失败。
5. `X-News-Cache`、`X-News-Rows-Read`、`Server-Timing: d1` 可核验单次实际公开请求。缓存命中的 D1 行数为 0；它不能代表整站全天成本。

完整观察日需按 UTC 日对比真实 GraphQL 用量，并结合请求数量、缓存命中率、新闻增长判断。刚部署后的同日累计读数包含旧版本消耗，不能拿它计算全天降幅。若需回退 Worker，新增索引可保留；回退不会删除新闻或改变订阅状态。
