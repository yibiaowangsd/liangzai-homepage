# PQC 迁移与密码敏捷检查表

用于自建测试与经授权的部署评估。勾选不是验收证明；零停机必须按实际协议生命周期演练。

## 1. 资产盘点

回答哪些连接、身份和历史数据暴露在迁移范围内。

退出条件：每项资产有负责人、数据保密期、协议版本与依赖清单。

- [ ] 登记入口、内部服务、VPN、SSH、设备、证书与第三方 SDK 的密码用途
- [ ] 记录 TLS/TLCP/SSH/IKE 版本、实际协商组、认证算法和供应商版本
- [ ] 标注数据保密期与先采集后解密风险，区分密钥协商和身份认证
- [ ] 列出证书签发、吊销、轮换、根信任库与 HSM / 加速器依赖
- [ ] 确认资产负责人、变更窗口、对端清单和最小支持版本
- [ ] 对企业资料完成公开边界确认；实验只用自建环境与临时测试数据

## 2. 确定优先级

按风险、影响面和依赖成本选择首批服务。

退出条件：形成可解释的优先级、明确的模式策略与验收阈值。

- [ ] 优先评估长保密期、外部可采集流量和高价值身份材料
- [ ] 分开制定兼容模式、优先混合模式和强制 PQC 模式的准入条件
- [ ] 验证所选算法、参数与协议编码在两端实现中一致
- [ ] 建立密码敏捷接口：算法标识、参数、密钥格式、错误码与版本可追踪
- [ ] 冻结基线版本并完成功能、拒绝路径、篡改、互通与弱网测试
- [ ] 明确握手失败率、P95、CPU、报文体积与降级次数的停止阈值

## 3. 灰度与零停机检查

在连接和证书生命周期内逐步放量，维持可观察性。

退出条件：新旧实例按计划共存，存量连接得到排空与明确的恢复验证。

- [ ] 先在自建回环与弱网环境验证，再选择可控的少量真实对端
- [ ] 服务端先具备新旧能力，对端升级顺序和证书算法兼容矩阵已确认
- [ ] 配置灰度比例、区域、服务身份与算法策略；避免运行时隐式回退
- [ ] 使用滚动替换、连接排空与负载均衡健康检查保留存量连接
- [ ] 对长连接、会话恢复、重新握手、重协商和证书轮换逐项演练
- [ ] 按最终协商组与认证算法监控成功率、HRR、重传和降级告警

## 4. 回退与收敛

可恢复不等于允许无声降级；回退也需要可审计的策略。

退出条件：故障演练、限时回退与最终收敛责任人均已确认。

- [ ] 演练失败阈值触发后的流量切回、配置恢复和连接排空
- [ ] 强制 PQC 服务默认失败关闭；策略放宽必须显式审批且限时
- [ ] 保留旧证书、依赖和配置的恢复能力，同时检查密钥撤销与审计要求
- [ ] 验证回退后业务、身份认证和协议策略仍满足既定最低要求
- [ ] 记录回退原因、影响面、最终协商组与重新放量条件
- [ ] 确定经典能力下线条件，更新资产台账和供应商兼容版本
