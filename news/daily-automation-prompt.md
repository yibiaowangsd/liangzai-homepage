更新并发布 wangyibiao.com 的七方向前沿日报，面向密码、网络安全与AI研发及产业读者，以重要、真实、新增、可解释的新闻为目标。使用已连接 GitHub 插件访问 yibiaowangsd/liangzai-homepage。先读取 main 最新的 news/README.md、news/editorial-policy.md、news/source-guide.md、news/edition-policy.json、news/validate-edition.py、.github/workflows/publish-news.yml 及最近7期 news/inbox/*.json，必要时查30天及更早相关事件。news/daily-automation-prompt.md 是本提示词的同步副本。不能沿用旧版五方向5×5、纯论文最多2条或必须有独立实现的配额要求。

以北京时间运行当天为日报日期。保持七栏目：pqc 后量子算法、migration 抗量子迁移、protocol 抗量子协议、standards 标准动态、security 网络安全、ai AI前沿、ngcc NGCC公钥征集。各方向目标3—5条、最多5条，允许0—2条；数量不构成保底任务，不以旧闻、维护小改动或营销稿凑数。七方向都要完成实际检索并记录覆盖；完全无合格新闻时不提交空日报，不清空已有内容。

一、先发现事件，再找直接证据
按 news/source-guide.md 的来源角色开展检索，该清单是开放入口，不是报道白名单。先用中英文主题词＋事件动作（研究/证明/攻击/评估/发布/试点/部署/事故/回滚/修复/撤回/征求意见/许可证或成本变化）做不限定机构的搜索，再定向查相关发布方和原始材料；使用算法/协议全称、缩写、中文名、旧名、版本号和文档号补检。不要一开始只翻wolfSSL、vLLM或固定几个GitHub仓库的commit；找到3条后也必须完成该栏主要来源类型的扫描。
每栏至少检查两种与该栏目相关的来源角色，并覆盖中文与海外线索；算法分别检查学术、企业研发、政府/评估与实现，迁移分别检查供给方方案和用户/行业组织实践，安全检查应急/PSIRT和实际事件/研究，AI检查模型/产品、研究/独立评测及应用/产业。没有材料可读时如实记录限制，不能伪称完成；这是检索义务，不是发稿配额。
国内外投入同等检索关注；海外按相关性覆盖欧洲/英国、北美和其他亚太地区，必要时查当地原文，不把“国外”等同美国。核心扫描指各栏按来源角色选取的代表性索引/公告/发布入口，以及下述必查NGCC入口；具体机构和全文依据候选深入。扩展来源按最近7期缺口轮换，同一来源/时间窗的有效检查跨栏复用，不机械重复查询，也不声称每日遍历整个清单。RSS/Atom、公开API、会议日程、邮件列表、数据库、媒体、社区和社交平台可用于发现，全文核验后才成稿。采用公开、实际可用的入口，不猜订阅地址，不绕过访问控制。

二、各栏新闻边界
pqc：KEM、数字签名及其他后量子公钥构造。重点新构造与技术路线、数学假设/安全模型、归约与证明、密码分析及经典/量子攻击复杂度、参数/安全级别、尺寸/效率与算法多样性；覆盖高校、企业和政府/评估机构的算法成果，也保留有实质价值的实现、国内密码库正式发布、硬件、测试向量、侧信道/故障、形式化验证和可复现基准。研究不要求先有代码、产品或部署。取消纯论文硬上限和非论文最低数量，按重大性选稿，同时复核连续7期是否被论文或某一密码库垄断。论文附代码不算第二个独立事件。一般QKD或量子计算新闻不能替代PQC算法。
migration：国内外公司的迁移工作和技术方案，以及运营商、银行、电力、云服务等采用方的需求、采购/验收要求、试点、部署、失败与回滚。包括架构/白皮书/路线图、CBOM与资产盘点、密码敏捷、PKI/证书/HSM/密码库、混合/纯PQC、互通、性能/成本、兼容性、生命周期与退回风险。公开且有实质内容的新方案即可报道，不要求生产上线或代码发布。说明谁在做、适用对象、实施机制和交付阶段；不能仅报签约、获奖或口号。
protocol：重点TLS/TLCP、SSH、IKE/IPsec，兼顾QUIC、认证/密钥建立及相关PKI、CMS、S/MIME、DNSSEC、WebPKI等场景。关注协议机制与安全分析、KDF/组合、认证/证书、报文/MTU/分片、中间盒、互通、性能、真实部署与故障。单纯草案编号/流程变化归standards，实质机制和工程影响可在本栏深入；同一事件不跨栏重复。
standards：NIST/IETF/RFC/IANA、ETSI、ISO/IEC、ITU-T、3GPP及国内国标/行标/团标、评估和迁移规范、征求意见、勘误、撤回、组织决议和实施要求。核实编号、版本、原始/更新日期、适用范围与状态，区分个人提案、WG采纳、各类Last Call、IESG、RFC Editor与正式RFC及类别；公开邮件/会议提议不等于通过，行业白皮书不等于强制标准。只有可读元数据时仅陈述编号/状态，不编造未读条文。
security：重要漏洞及在野利用、攻击活动/威胁情报、供应链、勒索/泄露、身份、云网/工控/基础设施、密码实现安全、防御、执法/监管公开结果与事故复盘。补查CNCERT、CNVD/CNNVD、CISA KEV/CSAF、CERT-EU、JPCERT及相关地区CERT、厂商PSIRT、研究者披露和受影响机构回应。说明受影响版本/前提、证据、补丁与缓解；区分PoC、理论可利用、确认在野利用、KEV收录和修复，EPSS概率/CVSS严重度不能冒充已利用证据。没有安全影响证据的普通bug或测试改动不自动成为安全新闻。
ai：模型/权重/API、多模态/Agent、开发工具、开源项目、训练/推理/芯片与算力、效率/成本、真实应用、可靠性/安全、独立评测和影响技术采用的监管/许可证/产业变化。同步查技术报告、模型卡/系统卡、许可证、官方权重/代码及API可用性；补HELM、METR、MLCommons等原始评测与公开方法。区分研究/公布/预览/Beta/正式可用，厂商自测不写成独立验证，开权重不自动等于完整开源。商业/政策事件须有技术供应、成本、使用条件或行业采用的实质影响，不做融资宣传或股价播报。不能让推理框架的日常commit替代整个AI栏目。
ngcc：商用密码标准研究院ICCS的NGCC公钥征集，只报签名/KEM/密钥交换。每次实际检查 https://www.niccs.org.cn/ 的征集公告和算法评议入口，以及用户指定 https://ngcc.dev/、https://ngcc.dev/reports/index.html、https://ngcc.dev/report-classification.html；按事件追踪原始规格/提交包、作者公开回应、复现仓库、Performance、Side-Channel及修复/复测。哈希征集不凑数。

三、价值排序与来源集中复核
先排实质性算法/安全结论、重要标准与政策节点、具有具体适用价值的产品/方案/部署、显著攻击/事故及可复现测量，再考虑日常维护。单个commit/PR须由原始报告、issue、回归测试或实测明确实际受影响行为/范围、重要算法能力或可量化的显著性能变化，才考虑独立成稿；不能仅凭diff推演安全影响。日常加固、测试扩充、兼容小补丁原则上并入相关版本更新，重大新问题不必等待CVE编号或正式发行；日志、UI文字、重命名、零散测试、普通重构和边界清理不因有代码就入选。具有同一原因和影响的连续提交/修复合并为一个事件，发行新闻不能重复包装已报提交；不以读者对某技术的熟悉程度代替新闻价值。
在写稿前按研究机构/企业/项目、来源角色、事件类型和地区检查当期及近7期组合；GitHub、arXiv是托管平台，不等于一个机构，同集团多域名也不等于独立来源。某栏样本至少3条时，若同一机构/项目超过半数，或最近7期一类事件持续支配该栏，必须补检尚未检查的缺失类型并比较被放弃的高价值候选；当日已对同一缺口完成有效检索可复用结果；不得仅写“已注意多样性”。有充分重大性理由可保留集中报道并在coverage记录，不为分散强塞低价值新闻。

四、来源证据与读取失败处理
一手性按具体事实的直接来源判断。技术规格、安全证明、标准状态和修复结论必须追原论文/标准/官方记录/研究者原始报告/维护者资料；原创采访、文件调查、现场报道、原始独立评测也可作为其直接揭示事实的主来源。Reuters/AP/新华社/财新及专业安全科技媒体的原创报道可用于事件事实，转述技术结论仍追原始材料；聚合、转载、榜单和社交热度只作线索。
逐条实际阅读支持核心事实的全文、附件、release/changelog、必要代码/实验记录；不能把搜索摘要、论文摘要当全文。官方声明按声明归因，关注失败、负面实测、作者反驳、撤回与更正，不只报正向进展。争议性安全突破、重大性能或部署主张主动找独立验证/当事方已公开回应；找不到时写清单方证据，不能把多个转载当多方确认，不得假称已联系当事人或完成实验。
遇到403/空页/失效PDF/动态内容，查官方新版入口、附件、作者公开全文、可信机构仓库或原始发布的HTML/PDF等合法替代；跟随官方迁移说明并复核日期。检索未命中、无法读取、已读但无新增、材料不足、重复/低价值分别记录。未读取不算已核查；不能将一次失败写成该领域无新闻。
source_url 选实际阅读、直接支持核心事件的具体HTTPS原始发布/原创调查/原始评测页面，不用首页、聚合或搜索结果。正文在相关事实附近用Markdown给其他关键证据链接，末尾可简列来源与日期；保持当前Schema，不自行增加接口字段。同一来源的复述遵守许可及当次引用/归纳限额，以多来源核实和独立组织的中文综述为主，不将媒体整稿或论文近似全文翻译。

五、时效、去重与NGCC核验
优先运行前24小时，缺稿时扩大到72小时、最多7天；原始事件日期、首次发布日期、实质更新日期、本站发布日期分开，抓取/转载/网页页脚日期不能充作新发布时间。7天外主要作背景；确需首次介绍有价值的旧成果，明确“技术回顾”与原始日期，全期最多2条、单栏最多1条，且不重报。重大新修复/撤回/状态变化可作为新进展，但明确旧事件与本次增量。
读取 https://api.wangyibiao.com/api/news/editions?page=1&pageSize=1 并逐页核对最近日报，或 https://api.wangyibiao.com/api/news?limit=100 补充；editions一天一页，pageSize=3不代表三期。与main最近7期共同建立去重清单，必要时查30天及早期相关稿。线上不可读时至少核对仓库并明确去重范围受限，不声称线上验证通过。按主体/版本/标准编号/CVE/finding ID/论文标识和关键事实去重；PDF/HTML、改标题/换媒体不算新事件。再次报道说明实质变化并链接前文。
NGCC逐条保留候选编号/名称、参数集、规范/实现版本、稳定finding ID、原始与更新日期、发现者Credit、本次变化及作者公开回应。区分设计/实现/侧信道层面、攻击前提、影响安全性质、声称安全级别、经典/量子及时间/内存/查询/电路复杂度。ngcc.dev是独立分析站，Severity/Status/Layer不等于ICCS官方评审；Confirmed不等于本站复现，Lead/Proof gap不等于攻破。秘密相关分支、测到泄漏、端到端恢复分开；理论低于声称强度不等于现实可执行；修复提出不等于复测通过，旧版漏洞不能直接套新版。记录未验证步骤、争议、撤回和修复版本，不把所有成果归维护者。

六、写作与兼容性
按当前v2输出严格JSON：{"schema_version":2,"date":"YYYY-MM-DD","coverage":{七类各含{"count":实际条数,"note":"覆盖说明"}},"items":[...]}。七类count与items一致，每类<=5；每类note简记实际查过的代表性机构/入口、来源角色、时间窗和主要排除/失败/待跟进项，即使达到3条也填写，最多600字；少于3条至少12字，不笼统声称全球无进展。coverage仅内部核验，不放入网页文章、邮件或机器人正文。重要但未成稿的短消息在note注明主题、日期和已核实入口供后续跟进，后续仍按原始时间判断，不重置为新新闻。
每篇含slug、title、summary、content、category、tags、source_name、source_url、cover_image、published_at、status。slug当日YYYYMMDD-开头、小写字母/数字/单连字符、唯一稳定。summary为100—180字中文；content通常600—1600字，现校验要求至少600字符、至少5个各>=50字符的实质段落，独立“## 量仔观察”后>=80字。开头明确ISO原始日期，实质更新另注明，回顾清楚标记。保持连续长文、少量小标题，以新闻事实和意义组织，再解释机制、证据、背景、适用范围和局限；不要逐段仿译原文，不堆术语或夸大标题。
新闻价值不以原始材料长度或是否有代码决定。对重要短公告先补同一事件的原始技术资料、适用对象、影响依据和已公开回应；仍不足以合规支撑长文则记入coverage待跟进，少报而不填充空话，不擅自降低现有校验或把无关短讯拼成长文。事实/作者主张/本站分析分清；性能注明参数、硬件、版本、基线、指标与局限，未知不补造，不混不可比数据。tags为非空字符串数组，可给真实事件类型；cover_image可null，由既有流水线兜底。published_at用本站实际发布时间ISO8601、全期同一北京时间日；status为published。

七、发布与回读
提交前运行 news/validate-edition.py，并逐项复核事实、来源可读性、日期/版本/状态、事件去重、新闻价值、来源集中性、版权和分析；结构通过不等于事实核验。只通过GitHub插件提交完整 news/inbox/YYYY-MM-DD.json 到main；当日已有文件先读最新版本，保留未改事件slug再整体替换，防止局部文件误删当日其他稿。用户已授权定时发布和main数据提交，无需每次确认；本次运行不得改应用代码、发布配置、订阅或其他自动化，不查看/输出/写入密钥。
既有publish-news.yml经Worker幂等upsert、同步当日清单。提交后查该SHA对应“Publish news to Cloudflare D1”最终状态与inserted/updated/skipped/removed，核对线上当期总数、七类计数及coverage。失败查日志，在数据修正范围内修复重试；基础设施/读取问题准确报告，不把commit成功当发布成功，不主动调用邮件/群机器人发送端点。最后中文简洁报告日期、实际总数/七类数、缺稿范围、提交及日报文件链接、流水线状态与取得的D1统计；不得虚报完成。
